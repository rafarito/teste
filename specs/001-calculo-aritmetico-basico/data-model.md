**Spec**: [spec.md](./spec.md)

## Contexto

O legado não possui banco de dados relacional — o histórico de cálculos era persistido em arquivo texto serializado, sem schema formal. A stack de destino introduz um banco relacional embarcado (H2) para o histórico, com schema versionado via Flyway. Não há schema legado a preservar ou migrar.

---

## Entidades

### HistoricoCalculo

Representa um cálculo aritmético realizado com sucesso e registrado no histórico.

| Campo | Tipo Java | Tipo SQL | Restrições | Descrição |
|-------|-----------|----------|------------|-----------|
| `id` | `Long` | `BIGINT` | PK, auto-increment | Identificador interno |
| `dataHora` | `LocalDateTime` | `TIMESTAMP` | NOT NULL | Data e hora em que o cálculo foi realizado |
| `operando1` | `String` | `VARCHAR(255)` | NOT NULL | Primeiro operando, exatamente como informado pelo usuário |
| `operando2` | `String` | `VARCHAR(255)` | NOT NULL | Segundo operando, exatamente como informado pelo usuário |
| `operacao` | `String` | `VARCHAR(20)` | NOT NULL | Símbolo da operação: `+`, `-`, `*`, `/` |
| `resultado` | `Double` | `DOUBLE PRECISION` | NOT NULL | Resultado numérico do cálculo |

**Observações:**
- `operando1` e `operando2` são armazenados como texto (o valor original digitado pelo usuário) para fidelidade ao histórico exibido.
- `operacao` armazena o símbolo matemático (`+`, `-`, `*`, `/`), não o identificador interno da operação.
- `resultado` é armazenado como número de ponto flutuante; a formatação pt-BR é aplicada apenas na camada de apresentação (frontend).
- Não há relacionamentos com outras entidades — `HistoricoCalculo` é uma entidade independente.

## Migration Flyway

```sql
-- V1__cria_tabela_historico_calculo.sql
CREATE TABLE IF NOT EXISTS historico_calculo (
    id         BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    data_hora  TIMESTAMP     NOT NULL,
    operando1  VARCHAR(255)  NOT NULL,
    operando2  VARCHAR(255)  NOT NULL,
    operacao   VARCHAR(20)   NOT NULL,
    resultado  DOUBLE        NOT NULL
);
```

**Nota**: A sintaxe acima é compatível com H2. Se o projeto migrar para PostgreSQL ou outro banco, a migration correspondente deve ser criada com a sintaxe adequada — o modelo de dados permanece o mesmo.

## DTOs (contratos de entrada/saída da API)

### CalculoRequestDTO (record — entrada)

| Campo | Tipo | Validação | Descrição |
|-------|------|-----------|-----------|
| `num1` | `String` | `@NotBlank` | Primeiro operando informado pelo usuário |
| `num2` | `String` | `@NotBlank` | Segundo operando informado pelo usuário |
| `operacao` | `Operacao` (enum) | `@NotNull` | Operação selecionada: `SOMA`, `SUBTRACAO`, `MULTIPLICACAO`, `DIVISAO` |

### CalculoResponseDTO (record — saída)

| Campo | Tipo | Descrição |
|-------|------|-----------|
| `resultado` | `Double` | Resultado numérico do cálculo |
| `historico` | `List<HistoricoItemDTO>` | Últimos N cálculos realizados (padrão: 5) |

### HistoricoItemDTO (record — item do histórico)

| Campo | Tipo | Descrição |
|-------|------|-----------|
| `dataHora` | `String` | Data e hora formatada (`yyyy-MM-dd'T'HH:mm:ss`) |
| `operando1` | `String` | Primeiro operando |
| `operando2` | `String` | Segundo operando |
| `simbolo` | `String` | Símbolo da operação (`+`, `-`, `*`, `/`) |
| `resultado` | `Double` | Resultado numérico |

---

## Enum Operacao

| Valor enum | Símbolo | Rótulo de exibição |
|------------|---------|--------------------|
| `SOMA` | `+` | Soma |
| `SUBTRACAO` | `-` | Subtracao |
| `MULTIPLICACAO` | `*` | Multiplicacao |
| `DIVISAO` | `/` | Divisao |

## Modelo de Interfaces TypeScript (frontend)

```typescript
export interface CalculoRequestDTO {
  num1: string;
  num2: string;
  operacao: 'SOMA' | 'SUBTRACAO' | 'MULTIPLICACAO' | 'DIVISAO';
}

export interface CalculoResponseDTO {
  resultado: number;
  historico: HistoricoItemDTO[];
}

export interface HistoricoItemDTO {
  dataHora: string;    // ISO 8601
  operando1: string;
  operando2: string;
  simbolo: string;
  resultado: number;
}
```
